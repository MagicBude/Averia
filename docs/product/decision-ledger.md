# Grilling 决策台账

## 用途

这份台账把项目开始编码前的产品访谈（问题 1–92）整理成可追溯的设计基线。它不是聊天记录的逐字副本，而是把已经确认的答案规范化为：

1. 决策内容
2. 约束或反例
3. 对应文档与实现状态

后续实现、评审和路线调整都应先检查本台账。若需要改变已确认边界，必须更新对应 ADR 或产品文档，并在这里记录变更原因；不能只在代码或聊天中隐式改变。

## 决策树总览

```text
可信的成人职业资料库
├─ 收录边界与安全策略
│  ├─ 只收录可验证的职业演员和正式发行作品
│  ├─ 排除年龄不明、疑似未成年、偷拍、泄露、非自愿和私人信息
│  └─ 安全模式默认，完整模式为本地会话偏好
├─ 资料模型
│  ├─ 人物、别名、职业时间线、组织关系
│  ├─ 作品、发行版本、出演关系、规范标签
│  └─ 来源、可信度、权利状态、审计记录
├─ 检索与浏览
│  ├─ 多语言与别名搜索
│  ├─ 组合筛选、排除条件、排序和可复制 URL
│  └─ 多页面路由；本地收藏不进入分享 URL
├─ 治理与贡献
│  ├─ 候选区 → 来源比较 → 人工审核 → 发布
│  ├─ 更正、权利、安全举报和合并拆分审计
│  └─ GitHub 白名单 OAuth 预留，服务端始终校验权限
└─ 工程边界
   ├─ TypeScript + React + Next.js + PostgreSQL
   ├─ 模块化单体；首期不引入微服务或独立搜索集群
   ├─ GitHub CI/CD；生产数据、媒体、凭据永不入库
   └─ MIT 代码许可；数据、图片和第三方内容另行遵守许可
```

## A. 产品定位与优先级（问题 1–8、27–28、62–68、83–86）

- 产品是中文优先的成人影视人物档案、作品关系和多维检索网站；界面先做中文，数据保留多语言姓名和原始标题。
- 第一阶段优先级为：专业档案与检索 > 影视卡片和海报浏览 > 日系杂志式字体层级、留白与细节。
- 首期不做榜单、个性化推荐和统计；完整多语言界面、账号同步、公开 API、真实 Provider 和本地视频管理延期。
- 顶级功能使用独立页面和路由，不用单页锚点模拟选项卡：`/people`、`/works`、`/graph`、`/about`、`/library`。
- 桌面提供完整筛选和后台密度；手机优先搜索、卡片、详情和收藏，但两端数据能力一致。
- 视觉上避免霓虹、廉价暗黑、过量渐变和传统成人视频站风格；安全模式与完整模式共享结构和品牌。

落点：[`product/overview.md`](overview.md)、[`product/ui-system.md`](ui-system.md)。

## B. 收录边界与人物字段（问题 3、19、24、26–28、38、47、64–66）

- 首期收录：职业演员、可验证的成人正式发行作品、非成人影视履历、公开职业社交链接。
- 严格排除：年龄不明、疑似未成年、偷拍、泄露、非自愿内容，以及住址、私人联系方式、真实身份等非职业私人信息。
- 人物核心字段：多语言姓名、艺名、曾用名及有效时期；出道、引退、复出等时间线；事务所、厂牌与合作关系；公开资料、简介、头像、来源、可信度；作品数量和最近发行时间。
- 身体尺寸、血型、兴趣等公开行业资料可以保存，但不作为首页主筛选维度；若开放高级筛选必须有限、可解释、可关闭。
- 模糊匹配只影响排序和命中提示，绝不触发自动人物合并；结果必须显示命中的是哪个别名或曾用名。
- 人物合并、拆分和高风险字段修改必须保留审计记录；旧项目真实数据不迁移。

落点：[`product/overview.md`](overview.md)、[`data/model.md`](../data/model.md)、[`safety/content-and-rights.md`](../safety/content-and-rights.md)。

## C. 作品、图片与安全/完整模式（问题 12、18、21–23、33–34、44、67–68）

- 安全模式默认：不请求、不渲染成人封面、剧照或露骨标题片段；使用文字、程序生成色块、首字母和排版封套。
- 不用“先加载原图再虚化”作为安全策略，因为模糊图仍可能泄露轮廓，也已经发生网络请求。
- 完整模式必须由用户主动确认成年后启用；默认只对当前浏览器会话有效，会话结束自动恢复安全模式；可选“在此设备记住”。
- 完整模式不生成独立可索引 URL；所有分享预览使用安全标题与安全图片。
- 每张图片必须记录来源、权利状态、最后验证时间；只有许可清楚的图片才缓存或托管，否则使用安全占位图或合法跳转。
- 作品模型分离内容主记录与发行版本，并记录作品编号、发行日期、介质、厂牌/发行商、系列、出演关系、标签和来源。

落点：[`safety/content-and-rights.md`](../safety/content-and-rights.md)、[`data/model.md`](../data/model.md)、[`product/ui-system.md`](ui-system.md)。

## D. 检索、排序与本地资料库（问题 14–16、29–31、35、54、58–59、71–72、87–92）

- 主筛选维度：姓名/别名、活跃年份、发行年份、厂牌/发行商、系列、出演关系、规范标签、活跃状态、收藏状态。
- 身体数据不作为主筛选入口；若开放，只放高级筛选并保持有限范围。
- 支持同组 OR、跨组 AND 和排除条件；筛选状态写入可复制 URL。
- 收藏状态、私有标签和备注只存在本地，不写入分享 URL；支持带版本号的 JSON 导出/导入。
- 默认排序为“相关度 + 数据完整度”，另支持发行日期、出道日期、名称和作品编号排序。
- 搜索归一化大小写、全半角、空格、连字符和多语言姓名；模糊匹配只改变排序并显示命中字段，不自动合并。
- 失败搜索词如未来记录，只能去关联化、短期保留、低频过滤并限制管理端访问；不记录收藏和备注。

当前实现：人物状态/出道年份、作品发行年份/厂牌/标签/出演关系、排除标签/出演者、排序和 URL 状态已完成第一批；系列实体、复杂表达式、大数据量服务端检索仍延期。

落点：[`data/local-library.md`](../data/local-library.md)、[`data/model.md`](../data/model.md)、[`product/roadmap.md`](roadmap.md)。

## E. 数据采集、审核和安全事件（问题 17、24、32–35、43、49–53、75–77、86–90）

- 外部资料只能进入候选区，经过来源比较、字段冲突检查、人工确认后才能发布；线上发布数据与工作草稿分离。
- 第一版先实现 TypeScript 可审查导入任务，并分为“获取原始数据—解析—归一化—人工确认”；只有复杂处理确实需要时才引入 Python。
- 第一版不承诺真实 Provider；可先收录结构化来源和候选导入，后续再决定公开 API 或完整数据集。
- 提供独立的更正、权利和安全举报入口；高风险举报先隐藏前台内容，再人工复核；不公开受害者删除细节。
- 普通失效页面可重定向；人物合并和拆分必须可逆并写审计日志。
- 管理后台首期采用 GitHub 白名单账号，服务端进行实际权限验证；权限模型预留未来多个可信管理员。

落点：[`data/editorial-workflow.md`](../data/editorial-workflow.md)、[`safety/content-and-rights.md`](../safety/content-and-rights.md)、[`architecture/overview.md`](../architecture/overview.md)。

## F. 技术、部署、许可和开源边界（问题 36–43、47–61、73–82）

- 技术栈：TypeScript、React、Next.js、Drizzle ORM、PostgreSQL；本机和公网统一 PostgreSQL，避免 SQLite/PostgreSQL 行为漂移。
- 使用模块化单体；首期不引入微服务、Redis、消息队列和独立搜索集群。
- 本机 Next.js 直接运行，PostgreSQL 由 Docker Compose 隔离；GitHub 负责代码、CI/CD 和部署工作流。
- 代码采用 MIT；生产数据库、图片、管理员配置、举报记录、采集凭据和真实数据不进入仓库；仓库只保留虚构或审查过的示例数据。
- GitHub OAuth 管理员白名单为首期方向；账号同步、公开 API、完整数据集和生产真实资料都在后续阶段。
- 代码和注释以教材级规范为目标：注释解释原因、边界和陷阱；每个迭代只引入少量新概念，并配套 README、ADR、自动测试和可运行验收路径。

落点：[`architecture/overview.md`](../architecture/overview.md)、[`architecture/adr/0001-postgresql-source-of-truth.md`](../architecture/adr/0001-postgresql-source-of-truth.md)、[`architecture/adr/0002-modular-monolith.md`](../architecture/adr/0002-modular-monolith.md)、[`operations/local-development.md`](../operations/local-development.md)、[`operations/deployment.md`](../operations/deployment.md)。

## G. 已确认但明确延期的分支

这些不是遗忘项，而是刻意保留的后续决策：

- 真实资料首批导入：等权利、托管、安全模式和人工审核验收后再决定。
- 公开 API、完整数据集、账号同步、贡献系统和更多管理员：等数据许可和维护压力被验证。
- 系列作为独立实体、复杂高级表达式、独立搜索服务：等数据规模和查询证据证明需要。
- 统计、榜单、个性化推荐：第二阶段。
- Docker 化 Next.js、生产对象存储和具体公网托管商：等部署政策和托管条款完成选择。

## 变更规则

当新需求与本台账冲突时，先判断它属于：

1. 不改变边界的实现细化：更新对应实现文档和测试。
2. 改变产品行为但不改变安全/权利边界：更新产品文档、路线和本台账。
3. 改变事实源、权限、审核、安全或许可边界：新增或更新 ADR，完成评审后再编码。

任何自动检查通过都不等于用户验收完成；每个可见功能都必须提供本机可操作的验收入口。
